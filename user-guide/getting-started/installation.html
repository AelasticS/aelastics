Installation

The synth CLI is distributed as a self-contained tarball from GitHub Releases. The tarball bundles Node.js and all dependencies; no separate Node install is required.

Two install paths are supported:

  1. Tarball install: the recommended path for end users.
  2. Build from source: for contributors and users who want the latest unreleased changes.

Tarball install​

Linux and macOS​

Pick the bundle for your platform from the Download page (or the latest release), extract it, and add the resulting synth/bin to your PATH.

# Choose one of:
#   synth-v0.2.0-linux-x64.tar.gz
#   synth-v0.2.0-linux-arm64.tar.gz
#   synth-v0.2.0-darwin-x64.tar.gz
#   synth-v0.2.0-darwin-arm64.tar.gz
VERSION=v0.2.0
TARGET=linux-x64         # adjust for your platform
URL="https://github.com/AelasticS/Synthesis/releases/download/cli-${VERSION}/synth-${VERSION}-${TARGET}.tar.gz"

# Download and extract under /usr/local
curl -L "$URL" | sudo tar -xz -C /usr/local

# Add synth to PATH (one-time, pick your shell's rc file)
echo 'export PATH="/usr/local/synth/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

Windows​

Download the matching synth-v0.2.0-win32-x64.tar.gz from the latest release and extract it (with 7-Zip, or tar -xzf in PowerShell 5+). Then add the extracted synth\bin folder to your user PATH:

# In an elevated PowerShell, after extracting to C:\synth
[Environment]::SetEnvironmentVariable(
  'Path',
  $env:Path + ';C:\synth\bin',
  [EnvironmentVariableTarget]::User
)

Open a new terminal for the PATH change to take effect.

Build from source​

For contributors, or to run the latest unreleased CLI:

Prerequisites​

  • Node.js ≥ 22: see nodejs.org or use nvm.
  • pnpm ≥ 9: see pnpm.io.
  • Rush ≥ 5: installed automatically by the build scripts; no manual install required.

Steps​

git clone https://github.com/AelasticS/Synthesis.git
cd Synthesis
node common/scripts/install-run-rush.js install
node common/scripts/install-run-rush.js rebuild

# Link the built CLI as `synth` on your PATH
cd apps/cli
pnpm link --global

synth --version

The linked synth binary points at apps/cli/bin/run.js in your clone, so any further rush build picks up source changes immediately.

To unlink:

cd apps/cli
pnpm unlink --global

Verifying the install​

synth --version
synth init
synth doctor
  • --version prints the installed CLI version.
  • init creates the workspace at ~/.synth/ (override with --path <dir>).
  • doctor runs a health check against the workspace and reports any problems.

In a terminal, synth is interactive where it helps: a bare synth transformation run walks you through pickers for the transformation, the input model, and the configuration consent. Piped, scripted, --json, --quiet, and CI invocations never prompt; they fail with strict, stable errors instead.

Shell completion​

Completion has two layers, set up once for bash or zsh.

1. Command and flag names, generated by the CLI:

synth autocomplete bash     # or: synth autocomplete zsh

and follow the printed instructions (they add an eval line to your shell's rc file).

2. Values: transformation names, model and configuration refs, pipeline names, and namespaces, completed context-aware from the workspace (after synth transformation run eer-to-relational, TAB on --in offers only models matching that transformation's source metamodel). This layer is a wrapper script shipped in the repository at apps/cli/scripts/completion/ (synth.bash and synth.zsh); copy the one for your shell anywhere and source it from your rc file after the autocomplete setup line, so its registration wins:

# ~/.bashrc (order matters)
eval $(synth autocomplete script bash)
source ~/path/to/synth.bash

On TAB the wrapper asks the CLI itself for the candidate values of the current position (a fast lookup over manifests and model headers; the engine is never loaded) and falls back to the command/flag completion when there are no value candidates. Completion is TAB-triggered only; bash and zsh are the first-class shells.

Upgrading​

Tarball install: re-run the install steps above with the new version. Replacing the extracted directory in place is enough; your workspace at ~/.synth/ is untouched.

Source install: git pull && node common/scripts/install-run-rush.js rebuild.

Uninstalling​

Tarball install:

sudo rm -rf /usr/local/synth
# remove the PATH entry you added in ~/.bashrc (or equivalent)

Source install:

cd apps/cli && pnpm unlink --global

The workspace at ~/.synth/ is not removed by either. Delete it manually if you want to discard all locally installed transformations, models, and pipelines:

rm -rf ~/.synth
