Templates

A model expression with no parameters and no computation is a model literal: it always evaluates to the same model. Add parameters and it becomes a model template, a function returning a model expression that describes a whole family of models from a single definition. This guide covers writing templates, instantiating them, and composing them; the algebraic view behind the terminology is in Concepts.

Parameterized templates​

Document pattern template​

A common pattern is a reusable model fragment parameterized by name. For example, a generic document pattern for EER models:

/** @jsx createExprNode */

function DocumentPattern(documentName: string): ExprNode<IEERSchema> {
  return (
    <e.EERSchema name={`${documentName}-Schema`}>
      <e.Kernel name={documentName}>
        <e.Attribute name={documentName}>
          <e.Domain name="string" />
        </e.Attribute>
        <e.Attribute name={`${documentName}ID`}>
          <e.Domain name="string" />
        </e.Attribute>
        <e.Weak name={`${documentName}Item`}>
          <e.Attribute name={`${documentName}ItemID`}>
            <e.Domain name="string" />
          </e.Attribute>
          <e.Attribute name={`${documentName}ItemDescription`}>
            <e.Domain name="string" />
          </e.Attribute>
        </e.Weak>
      </e.Kernel>
    </e.EERSchema>
  )
}

Instantiating for a specific document type:

const invoiceSchema = DocumentPattern("Invoice")

This produces an EER schema with a Kernel entity named "Invoice", attributes "Invoice" and "InvoiceID", and a Weak entity "InvoiceItem" with its own attributes. Calling DocumentPattern("PurchaseOrder") produces a structurally identical model with different names throughout.

Dynamic structure with computation​

Embed TypeScript expressions in curly braces to generate variable structure. Loops, conditionals, and any other TypeScript logic can appear inside JSX.

/** @jsx createExprNode */

interface IApprovalConfig {
  processName: string
  howManyApprovers: number
  isParallel: boolean
}

const DynamicApproval = ({ processName, howManyApprovers, isParallel }: IApprovalConfig) => {
  const tasks = Array.from({ length: howManyApprovers }, (_, i) =>
    <Task name={`approval ${i + 1}`} />
  )

  return (
    <Process name={processName}>
      <Sequence>
        <Task name="write proposal" />
        {isParallel
          ? <Parallel>{tasks}</Parallel>
          : <Sequence>{tasks}</Sequence>
        }
      </Sequence>
    </Process>
  )
}

A template whose single parameter is a props object is itself a JSX component, so it can be instantiated as a tag:

const myApproval = <DynamicApproval processName="Budget Review" howManyApprovers={3} isParallel={true} />

This generates a process with three parallel approval tasks. Changing the parameters produces a structurally different model. The Array.from and the conditional are computation operators embedded in the model expression.

Higher-Order Templates​

A higher-order template is a function that takes another template as a parameter, abstracting over the structure of sub-expressions: a value parameter selects among shapes a template already contains, while a template parameter supplies the shape itself. The example below is the workflow suite's executable sample, embedded from its source: the writing step is defined outside as a template (a plain task, or a two-task sub-process), the workflow takes the whole step template as a parameter, and evaluation happens in two steps, from higher-order template to template to model literal.

/** @jsx createExprNode */

/**
 * The documentation's higher-order template example, executable. The
 * writing step is a template of its own; the workflow is a higher-order
 * template taking the whole step template as a parameter; evaluation
 * happens in two steps, from higher-order template to template to model
 * literal. Import this model and run the suite's chain to see the
 * resulting process as a BPMN graph or a Mermaid diagram.
 */
import { createExprNode } from '@aelastics/synthesis/jsx'
import type { ExprNode, Template } from '@aelastics/synthesis/jsx'
import type { ModelStore } from '@aelastics/synthesis/store'
import { Process, Sequence, Task, Parallel, SubProcess } from 'workflow-metamodel'
import type * as wm from 'workflow-metamodel/model'

export const $synth = {
  kind: 'model',
  metamodel: 'workflow-metamodel',
  author: 'Sinisa Neskovic',
  version: '0.1.0',
  description: 'Approval workflow built from a higher-order template: the writing step is itself a template'
} as const

// Step templates, defined outside any workflow.
const Write = () => <Task name="Write" />

const ReviewedWrite = () => (
  <SubProcess name="WriteDocument">
    <Task name="Draft" />
    <Task name="ReviewDraft" />
  </SubProcess>
)

// The workflow as a higher-order template: the whole writing step is
// the parameter (any activity template qualifies, a plain task or a
// sub-process alike).
const Approval = (WriteStep: Template<wm.IActivity>) =>
  ({ doc, approvers }: { doc: string; approvers: number }) => (
    <Sequence name={`${doc}_main`}>
      <WriteStep />
      <Parallel name="approvals">
        {Array.from({ length: approvers }, (_, i) => (
          <Task name={`Approve${i + 1}`} />
        ))}
      </Parallel>
    </Sequence>
  )

// Two-step evaluation: applying the higher-order template to a step
// template yields an ordinary template; instantiating that closes the
// expression into a model literal. Swap ReviewedWrite for Write and the
// workflow's structure changes without touching its skeleton.
const ReviewedApproval = Approval(ReviewedWrite)

export default (store: ModelStore): ExprNode<wm.IProcess> => (
  <Process name="TemplatedApproval" store={store}>
    <ReviewedApproval doc="Contract" approvers={2} />
  </Process>
)

Because it is a workspace model like any other, you can run it and see the higher-order construction come out the other end as a diagram:

synth transformation install <path-to>/workflow-to-bpmn
synth transformation install <path-to>/bpmn-to-mermaid
synth model import <path-to>/sample/templated-approval.tsx --as demo/templated
synth transformation run workflow-to-bpmn bpmn-to-mermaid --in demo/templated --out-dir ./generated

The generated Mermaid flowchart shows the swapped structure: the sub-process write step from ReviewedWrite, then the parallel approvals. Replace Approval(ReviewedWrite) with Approval(Write) and only the writing step changes; the workflow skeleton is untouched.

Templates and transformation rules​

A transformation rule is a template whose parameter is a source model element: the same mechanism, applied once per matched element, with every invocation recorded in the trace. See Writing Transformations.
